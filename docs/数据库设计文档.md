# 数据库设计文档

> 项目：可配置内容源聚合与纯净阅读系统
> 数据库：MySQL 8.x，数据库名 `reader`，字符集 utf8mb4，存储引擎 InnoDB

---

## 1. 概述

本系统采用 MySQL 作为持久化存储，共设计 11 张数据表，覆盖用户与权限、新闻源与文章、书源与书籍、收藏与进度、行为与日志等核心数据。数据库设计遵循以下原则：

- **按用户隔离**：内容源、书架、收藏、进度等个人数据均以 `user_id` 归属，接口层按当前用户过滤。
- **双通道书籍**：书籍既可由用户上传（`source_id` 为空、记录 `uploader_id`），也可来自外部书源（记录 `source_id`），用 `source_id` 是否为空区分。
- **去重设计**：文章表以「来源编号 + URL 哈希」作为联合唯一键，避免多用户订阅同一源时互相去重。
- **统一进度**：阅读进度表用 `target_type` 统一记录文章（0）和书籍（1）的进度，文章记滚动位置，书籍记章节。

## 2. 命名与约定

- 表名、字段名统一使用小写蛇形命名（snake_case），如 `novel_book`、`review_status`。
- 主键统一为自增 `id BIGINT`。
- 时间字段使用 `DATETIME`，`created_at` 默认当前时间，`updated_at` 随更新自动刷新。
- 枚举类字段使用 `TINYINT` 或 `VARCHAR` 存储，含义在注释中说明。
- Java 实体与表字段通过 MyBatis 的驼峰映射（`map-underscore-to-camel-case`）自动对应。

## 4. 表关系说明

- `news_source.user_id` → `user.id`：新闻源归属用户，一对多。
- `article.source_id` → `news_source.id`：文章归属新闻源，一对多。
- `book_source.user_id` → `user.id`：书源归属用户，一对多。
- `novel_book.source_id` → `book_source.id`（书源书籍）；`novel_book.uploader_id` → `user.id`（上传书籍）。
- `novel_chapter.book_id` → `novel_book.id`：章节归属书籍，一对多。
- `bookshelf.user_id`/`book_id`、`article_favorite.user_id`/`article_id`：收藏关联关系。
- `reading_progress`、`user_behavior` 通过 `target_type + target_id` 通用关联文章或书籍。

说明：本系统通过 MyBatis 在业务层维护这些关联，未在数据库层强制外键约束，以避免删除源、书籍时受外键限制，孤儿数据由业务逻辑在删除时主动清理。

## 5. 关键设计说明

1. **文章去重键 `(source_id, url_hash)`**：新闻源按用户隔离，若按 URL 全局去重，两个用户订阅同一 RSS 源时，后抓取的用户会全部判重复，出现"抓取成功但入库 0 条"。改为来源与 URL 哈希组合去重后，每个用户的源各自维护文章副本。

2. **书籍双通道**：`novel_book.source_id` 为空表示上传书籍（记录 `uploader_id` 与 `review_status`），非空表示书源书籍。内部书库搜索只查 `source_id IS NULL AND review_status = 1`。

3. **审核状态机**：`review_status` 取值 0（待审核）→ 1（已通过）或 2（已驳回），通过后全站可见，驳回记录原因供上传者查看。

4. **进度统一模型**：`reading_progress` 用 `target_type` 区分文章和书籍，避免为两类内容分别建表。
