## 2. 核心算法设计

### 2.1 正文密度打分算法（HtmlCleaner）

用于从网页 HTML 中抽取正文，去除广告、导航、页脚。参考 Readability / Boilerpipe 思路。

**处理流程**：

1. Jsoup 解析 HTML，移除噪声节点（`script/style/nav/header/footer/aside/iframe` 及含 `ad/recommend/related/comment/share` 等 class/id 的节点）；
2. 遍历候选容器（`p/div/article/section/td/blockquote`），对每个块打分；
3. 选取得分最高的块作为正文；
4. 绝对化图片与链接，用 Safelist 白名单输出干净 HTML。

**打分公式**：

```
score = ownTextLength + punctCount × 2.0 + descParagraphLength × 1.5
若 linkDensity > 0.3，则 score ×= 0.3
```

- `ownTextLength`：块自身文本长度；
- `punctCount`：逗号/句号等标点数（中文正文特征，标点多表示正文）；
- `descParagraphLength`：块内所有 `<p>` 的文本长度之和（奖励"包含多个段落的正文容器"）；
- `linkDensity`：链接文本占比（占比高通常是导航/列表，扣分）。

> 注意：Jsoup 的 `Element.select("p")` 会包含元素自身，计算 descParagraphLength 时需跳过自身，否则段落会被重复计分。

**关键代码**（`HtmlCleaner.scoreBlock`）：

```java
double score = ownLen + punct * 2.0 + descPLen * 1.5;
if (linkDensity > 0.3) score *= 0.3;
```

### 2.2 书源规则引擎（RuleEngine）

书源规则是一个 JSON（`BookSourceRule`），描述小说站四个环节：

```
搜索(Search) → 详情(Detail) → 目录(Catalog) → 正文(Content)
```

**规则字段**（节选）：

| 字段 | 环节 | 含义 |
| --- | --- | --- |
| searchUrl / searchMethod / searchBody | 搜索 | 搜索地址模板 / GET或POST / POST请求体（`{{key}}` 关键词占位） |
| searchList / searchName / searchAuthor / searchCover / searchDetail | 搜索 | 结果列表 / 书名 / 作者 / 封面(src) / 详情链接(href) |
| bookUrlPattern | 详情 | 从详情URL提取 bookId 的正则 |
| detailName / detailAuthor / detailCover / detailIntro | 详情 | 详情页字段 |
| tocUrl | 详情 | 目录地址模板（`{{bookId}}` 或 `{{bookUrl}}` 占位） |
| catalogList / catalogName / catalogUrl | 目录 | 章节列表 / 章节名 / 章节链接 |
| contentUrl / bookContent | 正文 | 正文地址模板（`{{chapterUrl}}`）/ 正文选择器 |

**选择器约定**：以 `//` 或 `.//` 开头为 XPath，其余为 CSS 选择器。文本字段额外支持提取方式（`text/title/alt/html/ownText/textNodes/content`）。

**占位符渲染**：`{{key}}`（关键词，URL 编码）、`{{page}}`（页码）、`{{bookId}}`、`{{bookUrl}}`、`{{chapterUrl}}`。

**流程**（以搜索为例）：

```java
String encodedKey = URLEncoder.encode(keyword, UTF_8);
String searchUrl = buildUrl(rule.url, render(rule.searchUrl, {key, page}));
String html = "POST".equals(rule.searchMethod)
        ? httpFetcher.post(searchUrl, render(searchBody), charset, headers)
        : httpFetcher.get(searchUrl, charset, headers);
Document doc = Jsoup.parse(html, searchUrl);
Elements list = select(doc, rule.searchList);
for (Element item : list) {
    name = firstText(item, searchName, searchNameType);
    detailUrl = firstAttr(item, searchDetail, "href");
    ...
}
```

### 2.3 个性化排序（RankService）

```
score = α · normalize(源权重) + β · timeDecay(发布时间) + γ · behaviorScore(行为)
```

- 源权重归一化：`weight / 10`（1～10 映射到 0～1）；
- 时间衰减：`0.5 ^ (距今天数/半衰期小时)`，默认半衰期 24 小时；
- 行为分：点击次数（封顶 10 次 × 0.05）+ 读完（+0.5）；
- 系数默认 `α=0.5, β=0.3, γ=0.2`，可在 `application.yml` 调整。

### 2.4 JWT 认证（JwtUtil + AuthInterceptor）

- 登录成功后用 jjwt 签发 Token（HS256，subject=userId，含 username、过期时间）；
- 前端请求头带 `Authorization: Bearer <token>`；
- `AuthInterceptor` 拦截 `/api/**`（放行 `/api/auth/register`、`/api/auth/login`），解析 Token 并把 userId 写入 `UserContext`（ThreadLocal）；
- 密码用 BCrypt 加密存储与校验。

## 3. 模块详细设计

### 3.1 新闻抓取（NewsFetchService）

```
fetchSource(source)
├── type=0: fetchRss(source)
│     ├── GET RSS → RssParser.parse（RSS2.0/Atom）
│     └── 逐条 insertArticle（拉详情页 → HtmlCleaner 清洗 → 幂等入库）
└── type=1: fetchWeb(source)
      ├── GET 列表页 → 按 listSelector 提取文章链接
      └── 逐条拉详情页 → 清洗 → 入库
最后：更新 last_fetch_at，刷新 Redis 缓存，写 fetch_log
```

- **幂等去重**：`url_hash = SHA-256(url)`，先查重再插入；
- **兜底**：详情页抓取失败时用摘要作为正文。

### 3.2 缓存（NewsCacheService）

- Redis ZSET，key=`feed:candidates:{userId}`，member=articleId，score=publishedAt 时间戳；
- `refresh(userId)`：查询用户最近 500 篇文章写入 ZSET，TTL 6 小时；
- `getCandidateIds(userId)`：取最近 500 个 ID；
- Redis 异常时捕获并返回空，由业务层回源 MySQL（降级）。

### 3.3 资讯流（ArticleService）

```
feed(userId, sourceId, page, size)
├── 从 Redis 取候选 ID（未命中则查库）
├── 加载文章、源权重、行为、收藏集合
├── 逐条按 RankService 打分排序
└── 内存分页返回 ArticleVO
```

### 3.4 书源导入与转换（LegadoRuleConverter + BookSourceService）

- `importJson(userId, jsonText)`：解析 JSON（单个或数组），自动识别 legado 格式与本系统格式；
- legado 格式经 `convert()` 转换：`ruleSearch/ruleBookInfo/ruleToc/ruleContent` 结构 + 选择器 DSL（`class./id./tag./@css:/@xpath:`、`.N` 索引、`##正则`、`||`、`!N`、`@text/@title/@alt/@href/@src` 提取、POST 配置）→ 本系统规则；
- `reconvertAll(userId)`：对已导入书源原地重新解析，用于升级转换器后修复旧数据；
- JS（`@js:`/`<js>`）与 JSON 接口（`$.field`/`$[*]`）不支持，转换后对应字段为空。

### 3.5 小说搜索（NovelService）

- 遍历启用书源，**并行**搜索（固定 8 线程池，单源 15s 超时）；
- 单源失败（超时/反爬/JS）跳过并记日志，不影响其它源；
- 按书名+作者去重，标记是否已在书架。

### 3.6 目录与章节（NovelService）

- `catalog`：首次访问抓取目录页，**批量插入**章节（每 500 条一批），后续直接查库；
- `chapterContent`：章节无正文时按规则抓取并清洗（`wholeText()` 保留段落换行），缓存入库；返回上一章/下一章 ID。

### 3.7 抓取调度（NewsFetchScheduler）

- `@Scheduled(fixedDelay=60s)` 每分钟扫描"到期且启用"的新闻源；
- 到期的源调用 `fetchSource`；整体 try-catch，数据库不可用时降级不崩溃。

## 5. 错误处理

- 业务异常统一 `BizException`，由 `GlobalExceptionHandler` 转成 `{code,message}` 返回；
- 参数校验失败返回 400 与具体字段错误；
- 抓取失败不抛出到用户层，记录 `fetch_log` 与 warn 日志；
- 401（未登录/过期）由拦截器与异常处理统一处理，前端跳转登录页。

## 6. 已知局限

- 书源规则不支持 JS（`@js:`/`<js>`）、JSON 接口（`$.field`）、Cloudflare 人机验证；
- 单源 HTTP 抓取有超时（默认 10s），反爬较强的站点可能抓取失败；
- 新闻正文抽取为启发式算法，对结构极其特殊的页面可能不准（可用网页源自定义选择器兜底）。
