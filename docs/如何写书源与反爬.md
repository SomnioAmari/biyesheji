# 如何手写书源 + 反爬配置

> 本系统的书源规则是我们自己定义的简化格式，不追求兼容 legado 的全部高级语法。
> 本文讲清楚：① 书源规则怎么写；② 遇到反爬怎么配。

## 1. 我们的书源规则结构

一个书源 JSON 长这样（完整字段）：

```json
{
  "name": "某书籍站",
  "url": "https://www.example.com",
  "charset": "UTF-8",
  "userAgent": "Mozilla/5.0 ...",
  "headers": { "Referer": "https://www.example.com/" },
  "searchUrl": "/search?q={{key}}",
  "searchMethod": "GET",
  "searchBody": "keyword={{key}}",
  "searchList": ".book-item",
  "searchName": "h3 a",
  "searchAuthor": ".author",
  "searchCover": "img",
  "searchDetail": "h3 a",
  "bookUrlPattern": "/book/(\\d+)",
  "detailName": "h1",
  "detailAuthor": ".info .author",
  "detailCover": ".cover img",
  "detailIntro": ".intro",
  "tocUrl": "/book/{{bookId}}/catalog",
  "catalogList": "#list dd",
  "catalogName": "a",
  "catalogUrl": "a",
  "contentUrl": "{{chapterUrl}}",
  "bookContent": "#content"
}
```

### 字段语义

| 字段 | 含义 |
| --- | --- |
| `name` / `url` | 书源名 / 首页地址（相对链接会基于它补全） |
| `charset` | 网页编码，GBK 站填 `GBK`，默认 UTF-8 |
| `searchUrl` | 搜索地址模板，`{{key}}`=关键词，`{{page}}`=页码 |
| `searchMethod` / `searchBody` | GET 可省略；POST 搜索填 `POST` 和请求体模板 |
| `searchList` | 搜索结果列表项选择器 |
| `searchName` / `searchAuthor` | 书名 / 作者（取文本） |
| `searchCover` / `searchDetail` | 封面（取 src）/ 详情链接（取 href） |
| `bookUrlPattern` | 从详情 URL 提取 bookId 的正则（第一个分组） |
| `detailName` / `detailAuthor` / `detailCover` / `detailIntro` | 详情页字段 |
| `tocUrl` | 目录地址模板，`{{bookId}}` 占位；目录在详情页时填 `{{bookUrl}}` |
| `catalogList` / `catalogName` / `catalogUrl` | 目录列表 / 章节名 / 章节链接 |
| `contentUrl` | 正文地址模板，`{{chapterUrl}}` 占位（一般直接透传） |
| `bookContent` | 正文选择器 |

选择器：`//` 或 `.//` 开头是 XPath，其余是 CSS 选择器（`css:` 前缀也行）。

## 2. 反爬配置（重点）

### 2.1 自定义请求头（每个书源单独配）

```json
{
  "name": "某书籍站",
  "url": "https://www.example.com",
  "userAgent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/120.0 Safari/537.36",
  "headers": {
    "Referer": "https://www.example.com/",
    "Cookie": "PHPSESSID=xxx"
  }
}
```

- `userAgent`：伪装浏览器 UA（默认已是 Chrome UA，一般不用改）
- `headers`：额外请求头，**Referer / Cookie** 是最常用的两个反爬字段

### 2.2 SSL 证书信任（全局开关）

部分站点 SSL 证书不规范，Java 默认校验会报 `certificate_unknown` 错误。
在 `backend/src/main/resources/application.yml` 里：

```yaml
app:
  fetch:
    trust-all-certs: true   # 信任所有证书，修掉"证书错误"；有安全风险，默认 false
```

> ⚠️ 这会关闭 HTTPS 证书校验，只建议对你自己信任的站点开启。

### 2.3 常见反爬现象与对策

| 现象 | 对策 |
| --- | --- |
| 返回 403 | 加 `headers.Referer`；换 `userAgent` |
| 返回空/乱码 | 检查 `charset`（GBK 站很常见） |
| 证书错误 | 开 `trust-all-certs` |
| 需要登录 Cookie | 浏览器复制 Cookie 填进 `headers` |
| 需要 JS 渲染 / Cloudflare 人机验证 | ❌ 本系统不支持（需要真浏览器） |

## 3. F12 实战：给一个真实网站写书源

以任意一个无反爬的简单书籍站为例：

**第 1 步：找搜索接口**
搜索页输入"斗破苍穹"，看地址栏：`/search?q=斗破苍穹` → `searchUrl` 填 `/search?q={{key}}`

**第 2 步：写搜索结果规则**
F12 打开，点左上角"选取元素"，点搜索结果里的一本书：
- 列表项外层 → `searchList`（如 `.book-item`）
- 书名元素 → `searchName`（如 `h3 a`）
- 作者 → `searchAuthor`
- 封面 `<img>` → `searchCover`
- 详情链接 `<a>` → `searchDetail`

**第 3 步：写详情规则**
点进详情页：
- 书名 → `detailName`（如 `h1`）
- 作者 → `detailAuthor`
- 简介 → `detailIntro`
- 目录链接规律 → 确定 `bookUrlPattern`（如详情 URL 是 `/book/123`，则填 `/book/(\\d+)`）和 `tocUrl`

**第 4 步：写目录规则**
目录页：
- 章节列表容器 → `catalogList`（如 `#list dd`）
- 章节链接 → `catalogName` / `catalogUrl`（都是 `a`）

**第 5 步：写正文规则**
章节页：
- 正文容器 → `bookContent`（如 `#content`）

**第 6 步：到「书源管理」页粘贴 JSON → 保存 → 搜索验证**
