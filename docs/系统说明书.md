# 系统说明书（答辩讲解用）

> 本文面向开发者本人，把系统每个板块、每个功能的完整链路讲清楚，便于被问到任何一个功能都能讲明白。
> 技术栈：后端 Spring Boot 3.5 + MyBatis + MySQL 8 + Redis；前端 Vue 3 + Element Plus + Pinia + Vue Router + Axios。

---

## 1. 系统总览

系统是一个前后端分离的「纯净阅读」网站，分**新闻**和**书籍**两个板块，带**用户/管理员**双角色。

- **新闻板块**：用户配置 RSS/网页源 → 系统定时抓取并清洗正文入库 → 主页按个性化规则排序展示 → 阅读/收藏/进度。
- **书籍板块**：两条通道——① 用户上传 TXT、管理员审核入库（内部书库）；② 导入书源规则、按书名搜索外部书籍。支持书架、进度、可调排版、长章节分页、朗读。
- **管理员**：用户管理（启用/禁用/角色/重置密码）、书籍审核（通过/驳回/删除）。

后端分层：Controller（接口）→ Service（业务）→ Mapper（MyBatis 注解 SQL）→ MySQL/Redis。通用组件：HTTP 抓取、Jsoup 正文清洗、RSS 解析、章节拆分、书源规则引擎。

## 2. 用户认证与权限（完整链路）

### 2.1 注册

1. 前端 `Register.vue` 表单提交用户名/密码/昵称/邮箱。
2. 调 `POST /api/auth/register`（该接口在拦截器中免鉴权）。
3. `AuthService.register()`：校验用户名唯一 → 密码 BCrypt 加密 → `role=0`（普通用户）、`status=1`（正常）→ `UserMapper.insert`。
4. 数据库 `user` 表插入一条记录。

### 2.2 登录

1. `POST /api/auth/login` → `AuthService.login()`。
2. 按用户名查用户 → BCrypt `matches` 比对密码 → 生成 JWT（`JwtUtil.generateToken`，subject 存 userId，7 天有效期）。
3. 返回 `{ token, user }`，前端存 localStorage（Pinia `user store`）。

### 2.3 请求鉴权（每个请求都会走）

1. `AuthInterceptor` 拦截 `/api/**`（除 register/login 外）。
2. 从请求头取 `Authorization: Bearer <token>` → `JwtUtil.parseUserId` 解析出 userId。
3. 用 userId 查库，拿到**最新**的 `role` 和 `status`（保证角色/禁用实时生效，而不是只信 JWT）。
4. 若 `status=0`（禁用）→ 返回 403「账号已被禁用」。
5. 把 `{userId, role, username}` 存入 `UserContext`（ThreadLocal），请求结束后清除。
6. 业务代码用 `UserContext.require()` 拿当前用户 id；管理员接口用 `UserContext.requireAdmin()` 校验 `role==1`。

### 2.4 默认管理员

`AdminInitializer`（启动时执行一次）：若不存在 `admin` 用户，则创建 `admin/admin123`（BCrypt 加密，role=1）。

## 3. 新闻板块

### 3.1 新闻源管理（在「设置 → 新闻源」）

- 数据表 `news_source`：`user_id`（归属）、`type`（0=RSS / 1=网页源）、`url`、`category`、`weight`（权重，排序用）、`fetch_interval`（抓取间隔分钟）、`enabled`、`rule_json`（网页源选择器）。
- 接口 `GET/POST/PUT/DELETE /api/news-sources`，全部按 `UserContext.require()` 过滤当前用户。
- 一键「添加推荐源」：前端 `recommended.js` 内置 5 个已测 RSS（少数派、Solidot、阮一峰、博客园、月光博客），按钮遍历调用 `createNewsSource`，按 URL 去重。

### 3.2 新闻抓取与入库（核心链路）

触发方式：① 手动点「抓取」`POST /api/news-sources/{id}/fetch`；② 定时任务 `NewsFetchScheduler` 扫描到期源。

**RSS 源链路**（`NewsFetchService.fetchRss`）：
1. `HttpFetcher.get(url)` 抓取 XML。
2. `RssParser.parse()` 用 Jsoup XML 解析，兼容 RSS 2.0（`<item>`）和 Atom（`<entry>`），提取 title/link/author/pubDate/description。
3. 对每条 `insertArticle`：抓详情页 URL → `HtmlCleaner.extractContent` 正文清洗；抓失败就用摘要兜底。
4. `saveArticle`：算 `sha256(url)`，按 `(source_id, url_hash)` 查重，不存在才 `articleMapper.insert`。
5. 写 `fetch_log`，更新 `last_fetch_at`，`NewsCacheService.refresh` 刷新缓存。

**正文清洗**（`HtmlCleaner`）：Jsoup 解析 → 移除 script/style/nav/广告节点 → 对文本块按"文本密度 + 链接密度"打分 → 取最高分块 → 白名单标签净化。

> **关键点（曾被问到/踩坑）**：`article` 表的去重唯一键是 `(source_id, url_hash)`，而不是全局 `url_hash`。因为新闻源是按用户隔离的，若两个用户订阅同一 RSS，全局去重会导致第二个用户「抓取成功但入库 0 条、新闻不显示」。改成按 source 去重后，每个用户的源各自拥有自己的文章副本。

### 3.3 主页资讯流（个性化排序）

1. `GET /api/articles` → `ArticleService.feed(userId, sourceId, page, size)`。
2. 先读 Redis 候选集 id（`NewsCacheService.getCandidateIds`），没有就 `articleMapper.findRecentByUserAndSource` 查最近 500 条。
3. 收集源权重、用户行为、收藏状态。
4. 按 `score = α·源权重 + β·新鲜度(时间衰减) + γ·行为分` 排序（`RankService`，系数在 application.yml 可调）。
5. 分页返回 `ArticleVO`（标题/来源/摘要/时间/是否收藏）。

### 3.4 文章阅读与收藏

- `GET /api/articles/{id}` → 返回正文（清洗后的 HTML）＋ 是否收藏 ＋ 阅读进度；同时 `UserBehaviorMapper.upsert` 记录点击。
- 收藏：`POST/DELETE /api/articles/{id}/favorite` → 写/删 `article_favorite`。
- 阅读进度：`PUT /api/progress`，文章记 `scroll_position`（0~1），滚动监听定时上报。
- 朗读：见 5.3。

## 4. 书籍板块

### 4.1 书籍上传与审核（核心链路）

**上传**（`POST /api/novel/upload`，multipart：书名/作者/分类/简介/封面图/TXT 文件或粘贴全文）：

1. `NovelManageService.upload`：
   - `resolveText` 识别编码：先看 BOM（FF FE=UTF-16LE，FE FF=UTF-16BE），再试 UTF-8（出现替换符则回退 GBK）。
   - `ChapterSplitter.split` 拆分章节（见下）。
   - `FileStorageService.saveCover` 存封面到 `uploads/covers/`，返回 `/uploads/covers/xxx`。
   - 插 `novel_book`（`source_id=null`、`uploader_id=当前用户`、`review_status=0` 待审核）。
   - 批量插 `novel_chapter`（含正文 content，`url` 为空）。

**章节拆分**（`ChapterSplitter`，重点讲解点）：
- 识别标题：`第X章/节/回/卷/部/篇/幕`、`Chapter X`、`序章/序幕/序言/楔子/引子/前言/后记/尾声/番外/开篇`。
- 兼容：二字标题带空格（"序 幕"→"序幕"）；标题带书名前缀（"龙族3 第一幕 标题"）；标题下一行的短副标题合并进章节名（"第一幕"+"卡塞尔之门"）。
- 净化：拆分后**过滤空章节**（目录把章节名列一遍会产生空章节）；**汉字边界判断**避免把"前言后语"里的"前言"误判为标题。

**审核**（管理员，`/api/admin/novels`）：
- 列表按 `review_status` 筛选（0 待审 / 1 通过 / 2 驳回）。
- `POST /api/admin/novels/{id}/review`：通过 → `review_status=1`；驳回 → `review_status=2` + 原因。
- 通过后，该书进入公共内部书库，所有用户可搜到、可阅读。

**我的作品**（`GET /api/novel/mine`）：按 `uploader_id` 查自己的上传，显示审核状态与驳回原因，可删除。

### 4.2 内部书库搜索

- `GET /api/novel/search?keyword=` → `NovelService.searchLibrary` → `NovelBookMapper.searchLibrary`（`WHERE source_id IS NULL AND review_status=1 AND (name/author LIKE ...)`）。
- 前端 `NovelSearch.vue`：进入页面先调 `searchLibrary('')` 显示「推荐书籍」（最新收录）；搜索后显示内部书库结果，并**始终**给「使用自定义书源搜索」按钮。

### 4.3 书源管理与书源搜索（规则引擎）

**书源管理**（「设置 → 书源」）：`book_source` 表存 `rule_json`（完整规则）。支持粘贴导入、URL 导入、一键「导入推荐书源」；legado 格式自动转换。

**规则引擎**（`RuleEngine`，重点讲解点）：
- 规则 JSON 描述四环节：`searchUrl/searchList/searchName/...`（搜索）、`detailName/detailAuthor/detailIntro/tocUrl`（详情）、`catalogList/catalogName/catalogUrl`（目录）、`contentUrl/bookContent`（正文）、`contentNextPage`（正文分页）。
- 选择器：`//` 开头走 XPath，否则走 CSS（Jsoup）。
- 占位符：`{{key}}`（关键词）、`{{bookId}}`（详情 URL 正则提取）、`{{chapterUrl}}`（章节链接）。

**搜索链路**（`GET /api/novel/search-sources` → `NovelService.searchSources`）：
1. 查当前用户启用的书源，多线程并行调用 `RuleEngine.search`。
2. 每源：`searchUrl` 替换关键词 → GET/POST 抓取 → `searchList` 选结果项 → 逐项取书名/作者/封面/详情链接。
3. 单源超时/失败跳过，聚合去重返回。

### 4.4 书籍详情/目录/章节阅读

**详情**（`GET /api/novel/{bookId}` → `NovelService.getDetail`）：
- `requireReadableBook` 权限判断：内部书（source_id=null）→ 审核通过所有人可见，待审/驳回仅上传者和管理员可见；书源书 → 仅该书源拥有者可见。
- 返回书名/作者/封面/简介/状态/是否在书架/章节数。

**目录**（`GET /api/novel/{bookId}/catalog`）：
- 内部书：直接返回已存章节（上传时已拆好）。
- 书源书：首次用 `RuleEngine.catalog` 抓目录页，解析章节列表批量入库缓存，后续直接读缓存。

**章节正文**（`GET /api/novel/{bookId}/{chapterId}`）：
- 内部书：直接返回已存 `content`。
- 书源书：正文为空则用 `RuleEngine.content` 实时抓取并缓存；返回上一章/下一章 id。

**章节分页拼接**（`RuleEngine.content`，重点讲解点）：
- 某些书源把长章节拆成多页（正文里有"第(1/3)页"）。
- 用 `contentNextPage` 选择器（如 `a#next`）找"下一页"链接，仅当链接是同一章节的 `{章节}_2.html`、`_3.html` 形式时才继续抓取拼接，避免误抓下一章；同时去掉"第(X/Y)页"标记。

### 4.5 书架

- 加入/移除：`POST/DELETE /api/bookshelf/{bookId}`（内部书要先 `requireReadableBook` 校验可读）。
- 列表 `GET /api/bookshelf`：返回书籍 + 章节数 + 阅读进度（读到第几章），「继续阅读」跳到最后章节。
- 前端 `Bookshelf.vue` 两个 Tab：**收藏的小说**（书架）与**收藏的新闻**（`article_favorite`）。

## 5. 阅读增强

### 5.1 阅读设置

- 章节阅读页 `ChapterReader.vue` 的设置抽屉：字号、行距、段落间距、字间距、字体、页宽、背景主题（白/米黄/护眼绿/羊皮纸/夜间/蓝 + 自定义色）。
- 设置存 localStorage（`reader-settings`），打开页面时读回。

### 5.2 长章节分页

- 章节正文按段落累计，每约 3000 字切一页，底部显示「上一页 / 第 X/Y 页 / 下一页」，切章回到第 1 页。

### 5.3 朗读（TTS）

- 用浏览器 `Web Speech API`（`speechSynthesis`）。
- 前端 `composables/useTts.js`（单例）：**分块朗读**（按段落切块，超长段落按句号再切，避免 utterance 过长被截断）、播放/暂停/恢复/停止、语速/音量/音色、`onChunk` 回调上报当前块。
- 小说：段落**高亮**（当前段淡蓝背景）；新闻：播放条显示「正在朗读：当前句」。
- 底部悬浮播放条 `components/TtsBar.vue`：播放/暂停、停止、语速、音色、朗读设置入口。
- 音色/语速/音量在「设置 → 朗读」里配置并试听。
- **架构预留**：上层只调 `speak(text, onChunk)`，后续可把内部换成调用后端 `/api/tts`（用户自带云端 TTS Key），页面代码不用改。

## 6. 管理员功能

### 6.1 用户管理（`/api/admin/users`）

- 分页列表（用户名/昵称模糊搜）。
- 启用/禁用（`PUT /users/{id}/status`）、设为/取消管理员（`PUT /users/{id}/role`）、重置密码（`PUT /users/{id}/password`）。
- 约束：**不能操作自己**（防止把自己禁用/降级导致锁死）。

### 6.2 书籍审核（`/api/admin/novels`）

- 列表按审核状态筛选；「查看」跳书籍详情（管理员可读待审书）。
- 「通过」→ `review_status=1` 入库；「驳回」→ 填原因；「删除」→ 删书及其全部章节。

## 7. 常见问题速答（FAQ）

- **新闻抓取"入库 0 条"？** 去重键是 `(source_id, url_hash)`，若另一个账号已抓过同一源，本账号需重新抓取；另外 V2EX/BBC 在本机网络连不通，已从推荐源移除。
- **上传书籍章节拆错/全是空章节？** 是"目录列了一遍标题"导致的，拆分后已过滤空章节；带空格的"序 幕"等也已兼容。
- **章节正文只有第一页？** 书源把长章节分页了，规则里 `contentNextPage` 会自动拼接多页。
- **上传报"url 不能为空"？** 上传书籍的章节无外部链接，`novel_chapter.url` 已改为可空。
- **书源名显示 `?????`？** 历史导入时编码错误，已修正；正常通过前端导入是 UTF-8，不会乱码。
- **为什么有管理员？** 双角色设计：用户上传书籍、管理员审核入库，保证内部书库内容质量，同时管理账号权限。
