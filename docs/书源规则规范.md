# 书源规则规范文档

> 本文档说明"纯净阅读"书籍板块的书源规则（Book Source Rule）JSON 结构、选择器语法与规则引擎工作原理。新增书籍站点只需编写一条规则 JSON 即可接入，无需改动后端代码。

## 1. 设计思路

规则引擎参考开源阅读（legado）的书源思路，将"接入一个书籍站"抽象为四个环节：

```
搜索(Search) → 详情(Detail) → 目录(Catalog) → 正文(Content)
```

每个环节由「URL 模板 + 选择器规则」描述。引擎按环节逐步抓取网页、用选择器提取字段，串成一条流水线。

## 2. 规则 JSON 完整结构

```json
{
  "name": "书源名称",
  "url": "https://www.example.com",
  "charset": "UTF-8",

  "searchUrl": "/search?q={{key}}",
  "searchList": "//div[contains(@class,'book')]",
  "searchName": ".//h3",
  "searchAuthor": ".//p[contains(@class,'author')]",
  "searchCover": ".//img",
  "searchDetail": ".//a",

  "bookUrlPattern": "/book/(\\d+)",
  "detailName": "//h1",
  "detailAuthor": "//div[contains(@class,'author')]",
  "detailCover": "//div[contains(@class,'cover')]/img",
  "detailIntro": "//div[contains(@class,'intro')]",
  "tocUrl": "/catalog/{{bookId}}",

  "catalogList": "//ul[contains(@class,'catalog')]/li",
  "catalogName": ".//a",
  "catalogUrl": ".//a",

  "contentUrl": "{{chapterUrl}}",
  "bookContent": "//div[@id='content']"
}
```

### 2.1 字段说明

| 字段 | 环节 | 含义 |
| --- | --- | --- |
| `name` | - | 书源名称 |
| `url` | - | 书源首页（用于相对 URL 补全） |
| `charset` | - | 网页编码，默认 UTF-8（GBK 站点填 `GBK`） |
| `searchUrl` | 搜索 | 搜索 URL 模板，`{{key}}` 为关键词占位 |
| `searchList` | 搜索 | 结果列表项选择器（每一项代表一本书） |
| `searchName` | 搜索 | 书名（取元素文本） |
| `searchAuthor` | 搜索 | 作者（取元素文本） |
| `searchCover` | 搜索 | 封面（取 `src` 属性） |
| `searchDetail` | 搜索 | 详情链接（取 `href` 属性） |
| `bookUrlPattern` | 详情 | 从详情 URL 提取 bookId 的正则，第一个捕获组为 bookId |
| `detailName` | 详情 | 书名 |
| `detailAuthor` | 详情 | 作者 |
| `detailCover` | 详情 | 封面 |
| `detailIntro` | 详情 | 简介 |
| `tocUrl` | 详情 | 目录 URL 模板，`{{bookId}}` 占位 |
| `catalogList` | 目录 | 章节列表项选择器 |
| `catalogName` | 目录 | 章节名（取文本） |
| `catalogUrl` | 目录 | 章节链接（取 `href`） |
| `contentUrl` | 正文 | 正文 URL 模板，`{{chapterUrl}}` 占位 |
| `bookContent` | 正文 | 正文内容选择器 |
| `contentNextPage` | 正文 | 正文「下一页」链接选择器（可选，用于章节内分页自动拼接） |

### 2.2 字段语义约定

引擎对字段"取文本还是取属性"做了约定，规则里无需写 `/text()` 或 `/@src`：

- **文本字段**（name / author / intro）：选中元素后取 `.text()`
- **封面字段**（cover）：选中元素后取 `src` 属性
- **链接字段**（detail / catalogUrl）：选中元素后取 `href` 属性

## 3. 选择器语法

| 写法 | 含义 |
| --- | --- |
| `//div[@class='book']` | XPath（绝对路径，作用于整页） |
| `.//h3` | XPath（相对路径，作用于当前列表项） |
| `.cover img` | CSS 选择器（默认） |
| `css:.cover img` | CSS 选择器（显式前缀，与默认等价） |

判定规则：以 `//` 或 `.//` 开头按 XPath 解析，其余按 CSS 选择器解析。XPath 由 Jsoup `selectXpath` 实现，CSS 由 Jsoup `select` 实现。

## 4. 占位符模板

| 占位符 | 出现位置 | 替换来源 |
| --- | --- | --- |
| `{{key}}` | `searchUrl` | 用户输入的关键词 |
| `{{bookId}}` | `tocUrl` | `bookUrlPattern` 正则从详情 URL 提取 |
| `{{chapterUrl}}` | `contentUrl` | 目录环节解析出的章节链接 |

模板支持相对路径：`/search?q={{key}}` 会相对 `url`（书源首页）补全为绝对地址；`{{chapterUrl}}` 本身已是绝对地址，直接透传。

## 5. 规则引擎工作流

```
搜索：render(searchUrl, {{key}}) → GET → select(searchList) → 逐项提取 name/author/cover/detailUrl
详情：GET(detailUrl) → 提取 name/author/cover/intro → 正则提取 bookId → render(tocUrl, {{bookId}})
目录：GET(tocUrl) → select(catalogList) → 逐项提取 name/url
正文：render(contentUrl, {{chapterUrl}}) → GET → select(bookContent) → wholeText() 提取纯文本
```

正文最终以纯文本（保留段落换行）入库，前端以 `white-space: pre-wrap` 展示，从源头规避广告与无关元素。

## 6. 引擎实现要点

- 相对 URL 用 `java.net.URI.resolve` 补全，兼容站点内相对链接
- 抓取用 JDK 内置 `HttpClient`（`java.net.http`），带超时与 UA
- XPath / CSS 双选择器：`RuleEngine.select()` 按前缀分派
- 单书源抓取失败不阻塞整体搜索，失败书源跳过并记录日志

## 7. 完整示例（带注释）

见 `docs/书源规则示例.json`。核心字段对应的网页结构示意：

```html
<!-- 搜索页 /search?q=xxx -->
<div class="book">
  <img src="/cover/1.jpg">
  <h3>书名</h3>
  <p class="author">作者</p>
  <a href="/book/123">详情</a>       <!-- searchDetail 取 href -->
</div>

<!-- 详情页 /book/123 -->
<h1>书名</h1>
<div class="author">作者</div>
<div class="intro">简介……</div>
<!-- tocUrl: /catalog/{{bookId}} → /catalog/123 -->

<!-- 目录页 /catalog/123 -->
<ul class="catalog">
  <li><a href="/chapter/1.html">第一章</a></li>
  <li><a href="/chapter/2.html">第二章</a></li>
</ul>

<!-- 章节页 /chapter/1.html -->
<div id="content">正文内容……</div>
```

## 8. 接入新书源的步骤

1. 用浏览器打开目标书籍站，找到搜索接口（通常是 `GET /search?关键词`）
2. 用 F12 查看搜索结果列表、书名、作者、封面、详情链接对应的 HTML 结构，写出选择器
3. 打开详情页，写出书名/作者/简介选择器与目录链接规律，确定 `bookUrlPattern` 正则
4. 打开目录页与章节页，写出目录与正文选择器
5. 在「书源管理」页粘贴规则 JSON → 保存 → 到「书籍搜索」验证

## 9. 导入 legado（开源阅读）书源

系统支持直接导入 legado 书源 JSON，无需手动改写成本系统的规则格式。

### 9.1 两种导入方式

- **粘贴导入**：书源管理页 →「粘贴导入」，粘贴 legado 书源 JSON（支持单个对象或合集数组）
- **URL 导入**：书源管理页 →「URL 导入」，输入指向书源 JSON 的链接，系统自动抓取导入

### 9.2 自动转换的内容

| legado 字段 | 转换到本系统 |
| --- | --- |
| `bookSourceName` / `bookSourceUrl` | `name` / `url` |
| `ruleSearch.bookList` | `searchList` |
| `ruleSearch.name / author / coverUrl / bookUrl` | `searchName / searchAuthor / searchCover / searchDetail` |
| `ruleBookInfo.name / author / coverUrl / intro` | `detailName / detailAuthor / detailCover / detailIntro` |
| `ruleToc.chapterList / chapterName / chapterUrl` | `catalogList / catalogName / catalogUrl` |
| `ruleContent.content` | `bookContent` |
| `searchUrl`、`bookUrlPattern` | 同名字段 |

### 9.3 选择器语法转换

| legado 写法 | 转换结果 |
| --- | --- |
| `class.author@text` | `.author`（取文本） |
| `id.content@html` | `#content` |
| `tag.h3@text` | `h3` |
| `tag.a@href` | `a`（取 href） |
| `tag.img@src` | `img`（取 src） |
| `@css:.cover img@src` | `.cover img` |
| `@xpath://div[@class='xx']` | `//div[@class='xx']`（XPath） |

### 9.4 目录地址的处理

legado 的目录通常在书籍详情页上，因此导入后 `tocUrl` 会设为 `{{bookUrl}}`（用详情页地址作为目录地址），抓取目录时重新拉取详情页并应用目录选择器。

### 9.5 局限性

少数使用 `@json:`（JSON 接口）、正则、JS 脚本、`&&` 组合等高级语法的 legado 书源无法完整自动转换，导入后可到「编辑」里手动补全规则。
