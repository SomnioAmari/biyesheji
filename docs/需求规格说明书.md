# 需求规格说明书

## 基于 Spring Boot 的可配置内容源聚合与纯净阅读系统

---

## 1. 引言

### 1.1 编写目的

本文档描述"可配置内容源聚合与纯净阅读系统"的功能需求、非功能需求、数据需求与接口需求，作为系统设计、开发与测试的依据。

### 1.2 项目背景

见《开题报告》。核心诉求：把新闻资讯与小说书源统一管理，系统定时抓取、清洗正文后提供无广告的纯净阅读体验，并支持收藏、阅读进度与个性化排序。

### 1.3 术语定义

| 术语 | 定义 |
| --- | --- |
| 内容源 | 供系统抓取内容的数据源，分新闻源（RSS/网页源）与小说书源两类 |
| 书源 | 小说内容源，由"书源规则 JSON"描述如何抓取某个小说网站 |
| 正文清洗 | 从网页 HTML 中抽取正文并去除广告、导航等无关元素 |
| 书架 | 用户收藏的小说集合 |
| 个性化排序 | 按"源权重 + 新鲜度 + 行为"对资讯流排序 |

### 1.4 参考资料

- 《需求与总体方案设计》
- 《开题报告》
- 项目数据库脚本 `sql/schema.sql`

## 2. 总体描述

### 2.1 产品定位

一个网站版的"纯净阅读器"，分两个独立板块：**新闻板块**（定时拉取 + 缓存 + 个性化）与**小说板块**（书源规则 + 搜索 + 书架）。纯净阅读由后端正文清洗保证。

### 2.2 用户角色

| 角色 | 说明 |
| --- | --- |
| 普通用户 | 注册登录后，配置新闻源与书源，阅读个性化资讯与小说 |

系统采用单角色设计，不设管理员；内容源与书源均归属用户本人，天然形成个人空间隔离。

### 2.3 运行环境

- 服务端：JDK 17+、MySQL 8、Redis（可选）、Nginx
- 客户端：现代浏览器（Chrome / Edge）
- 支持响应式布局，适配移动端

## 3. 功能需求

### 3.1 功能模块总览

```
用户模块（注册/登录/个人空间）
├── 新闻板块
│   ├── 新闻源管理（RSS/网页源 CRUD、启停、权重、频率）
│   ├── 定时批量抓取 + 正文清洗 + 缓存
│   ├── 主页个性化资讯流
│   ├── 文章阅读 + 收藏 + 进度
└── 小说板块
    ├── 书源管理（书源规则 CRUD、粘贴/URL 导入）
    ├── 书名搜索（聚合多书源、无推荐）
    ├── 书籍详情 + 目录 + 章节阅读
    └── 书架 + 阅读进度
```

### 3.2 用户模块

| 编号 | 功能 | 描述 |
| --- | --- | --- |
| U-01 | 注册 | 用户名（唯一）、密码（BCrypt 加密）、昵称、邮箱 |
| U-02 | 登录 | 账号密码登录，签发 JWT Token |
| U-03 | 认证 | 前端携带 Token，后端拦截器校验；个人数据按 user_id 过滤 |
| U-04 | 个人空间 | 展示个人信息 |

### 3.3 新闻板块

| 编号 | 功能 | 描述 |
| --- | --- | --- |
| N-01 | 新闻源管理 | 新增/编辑/删除/启停 RSS 源与网页源，配置抓取频率、源权重 |
| N-02 | 定时抓取 | 按每个源的抓取频率周期触发，批量抓取一批新闻 |
| N-03 | 正文清洗 | 后端正文密度算法抽取正文，去除广告/导航/页脚 |
| N-04 | 幂等入库 | 按 URL 哈希去重，避免重复入库 |
| N-05 | 缓存 | 最近一批候选文章写入 Redis，主页读缓存排序 |
| N-06 | 主页资讯流 | 按"源权重 + 新鲜度 + 行为"打分排序，分页展示 |
| N-07 | 文章阅读 | 纯净正文展示、来源标注、原文链接 |
| N-08 | 文章收藏 | 收藏/取消收藏、收藏列表 |
| N-09 | 阅读进度 | 保存文章滚动位置百分比，再次进入自动定位 |
| N-10 | 抓取日志 | 记录每次抓取的时间、成功/失败、入库条数、失败原因 |

### 3.4 小说板块

| 编号 | 功能 | 描述 |
| --- | --- | --- |
| F-01 | 书源管理 | 书源规则 CRUD、启停；支持粘贴导入与 URL 导入 |
| F-02 | 书名搜索 | 用户输入书名/关键词，并行遍历启用书源，聚合去重结果，**不做任何推荐** |
| F-03 | 书籍详情 | 封面、书名、作者、简介、"加入书架" |
| F-04 | 目录 | 按书源规则抓取章节列表 |
| F-05 | 章节阅读 | 按需抓取章节正文并清洗，支持上下章切换 |
| F-06 | 书架 | 已收藏小说列表、阅读进度、继续阅读、移除 |
| F-07 | 阅读进度 | 记录"书 + 章节"，再次进入定位到上次章节 |

### 3.5 主要用例

**用例 UC-01：添加新闻源并浏览资讯**

```
主参与者：普通用户
前置条件：用户已登录
主流程：
  1. 用户进入"新闻源"页，新增一个 RSS 源（填名称、URL、权重、频率）
  2. 系统校验源可用性（试抓一次）
  3. 定时任务到点后批量抓取该源的文章，清洗正文并入库、写缓存
  4. 用户进入主页，看到按个性化规则排序的资讯流
  5. 用户点击文章，进入纯净正文阅读页
异常流程：抓取失败时记录抓取日志，用户可手动"立即抓取"
```

**用例 UC-02：导入书源并搜索小说**

```
主参与者：普通用户
前置条件：用户已登录
主流程：
  1. 用户进入"书源管理"页，粘贴或 URL 导入书源规则
  2. 用户在"小说搜索"页输入书名
  3. 系统并行遍历启用书源，聚合搜索结果
  4. 用户点击一本书，进入详情页
  5. 用户点"加入书架"，再查看目录、阅读章节
异常流程：单个书源抓取失败时跳过并记录日志，不影响其它书源
```

## 4. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 主页资讯流读缓存 < 300ms；正文清洗单篇 < 1s；单源抓取有超时（默认 10s） |
| 可用性 | 定时任务失败不阻塞整体；Redis 不可用自动降级回源 MySQL；小说搜索并行 + 单源超时 |
| 安全 | 密码 BCrypt 加密；JWT 无状态鉴权；个人数据按 user_id 隔离；正文白名单渲染防 XSS |
| 可维护性 | 分层清晰；新增书源改配置不改代码；抓取日志可观测 |
| 可扩展性 | 新闻/小说模块独立，底层抓取解析组件复用 |
| 兼容性 | 主流浏览器，响应式布局 |

## 5. 数据需求

### 5.1 核心实体

用户（user）、新闻源（news_source）、文章（article）、书源（book_source）、小说书（novel_book）、小说章节（novel_chapter）、书架（bookshelf）、文章收藏（article_favorite）、阅读进度（reading_progress）、用户行为（user_behavior）、抓取日志（fetch_log）。

### 5.2 ER 关系

```
user 1 ──< news_source >── fetch_log
             │                    │
             ▼(type=news)         ▼(type=novel)
          article            novel_book 1 ──< novel_chapter
             ▲                    ▲
user ──< article_favorite   bookshelf >── user
             ▲                    ▲
       reading_progress（target_type + target_id 通用）
       user_behavior（行为，供个性化排序）
```

### 5.3 关键数据字典（节选）

**article（文章）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT | 主键 |
| source_id | BIGINT | 所属新闻源 |
| title | VARCHAR(255) | 标题 |
| source_name | VARCHAR(100) | 来源标注 |
| url / url_hash | VARCHAR(500) / CHAR(64) | 原始链接 / 去重键（SHA-256） |
| summary / content | TEXT / LONGTEXT | 摘要 / 清洗后正文 |
| published_at | DATETIME | 发布时间（排序用，建索引） |

**book_source（书源）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT | 主键 |
| user_id | BIGINT | 归属用户 |
| name / url | VARCHAR | 书源名 / 书源首页 |
| rule_json | TEXT | 完整书源规则 JSON |
| enabled | TINYINT | 是否启用 |

**reading_progress（阅读进度，通用）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| user_id / target_type / target_id | BIGINT/TINYINT/BIGINT | 用户 / 类型(0文章,1小说) / 目标ID |
| chapter_id | BIGINT | 小说章节（文章为空） |
| scroll_position | DECIMAL(10,4) | 文章滚动百分比 |

> 完整建表 SQL 见 `sql/schema.sql`。

## 6. 接口需求

统一返回结构：`{ code, message, data }`；鉴权通过 `Authorization: Bearer <token>`。

| 模块 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 认证 | POST | `/api/auth/register` | 注册 |
| 认证 | POST | `/api/auth/login` | 登录 |
| 新闻源 | GET/POST/PUT/DELETE | `/api/news-sources` | 新闻源 CRUD |
| 新闻源 | POST | `/api/news-sources/{id}/fetch` | 立即抓取 |
| 资讯 | GET | `/api/articles` | 主页资讯流（分页、源筛选、个性化排序） |
| 资讯 | GET | `/api/articles/{id}` | 文章详情 |
| 资讯 | POST/DELETE | `/api/articles/{id}/favorite` | 收藏/取消 |
| 书源 | GET/POST/PUT/DELETE | `/api/book-sources` | 书源 CRUD |
| 书源 | POST | `/api/book-sources/import` | 粘贴导入 |
| 书源 | POST | `/api/book-sources/import-url` | URL 导入 |
| 书源 | POST | `/api/book-sources/reconvert` | 原地重转换 |
| 小说 | GET | `/api/novel/search` | 搜索 |
| 小说 | GET | `/api/novel/detail`、`/{bookId}` | 详情 |
| 小说 | GET | `/api/novel/{bookId}/catalog` | 目录 |
| 小说 | GET | `/api/novel/{bookId}/{chapterId}` | 章节正文 |
| 书架 | GET/POST/DELETE | `/api/bookshelf` | 书架 |
| 进度 | GET/PUT | `/api/progress` | 查询/上报进度 |
