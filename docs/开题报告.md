## 一、研究目的和意义

### 1.1 研究背景

随着移动互联网的普及，人们的阅读行为已从纸质媒介大规模转向电子媒介，网络新闻资讯与网络书籍成为日常阅读的主要内容。然而，当前主流的在线阅读体验仍存在突出问题，集中体现在三个方面：

第一，**阅读干扰严重**。新闻资讯网站与书籍站点为了商业变现，在页面中大量嵌入广告、弹窗、诱导链接和无关推荐，这些干扰元素不仅影响美观，更严重分散读者的注意力，尤其在移动端阅读体验急剧下降。

第二，**内容源分散，缺乏统一入口**。新闻内容通常来自不同的 RSS 订阅源与资讯站点，网络书籍则来自不同的书源网站，用户需要在多个应用与网站之间反复切换，无法在一个统一的入口中完成信息的获取、整理与阅读，使用成本高、效率低。

第三，**缺乏个性化与可定制性，且书源易失效**。资讯流的排序通常由平台算法统一决定，用户无法按照自身关注程度调整；书籍书源也经常因为站点改版、屏蔽等原因而失效，用户缺乏自行增补和维护书源的途径，只能被动接受平台提供的有限内容。

针对上述问题，本课题提出构建一个网站版的"纯净阅读器"，将新闻资讯源与书籍书源统一纳入"可配置内容源"的管理模型，由后端完成内容抓取、解析与正文清洗，从系统架构层面保证广告等无关信息不进入阅读页面；同时引入用户/管理员双角色，支持用户上传书籍、管理员审核入库，形成"内容源可配置、内容可沉淀、阅读可定制"的完整闭环。

### 1.2 研究目的

本课题旨在设计并实现一个基于 Spring Boot 的前后端分离阅读系统，系统分为新闻与书籍两个相互独立又共享底层能力的板块，并具备用户与管理员两类角色。具体目标包括：

1. 建立统一的内容源管理模型，支持新闻源与书源的统一配置、增删改与启停；
2. 实现后端正文清洗能力，通过正文密度打分与白名单标签保证前端展示的都是干净正文；
3. 实现新闻板块的定时抓取、缓存与个性化排序，形成"配置源 → 抓取 → 清洗 → 展示 → 收藏 → 进度"的完整资讯流；
4. 实现书籍板块的"上传审核入库 + 书源规则搜索"双通道，形成"上传 → 审核 → 内部书库 → 搜索 → 书架 → 阅读"的完整阅读闭环；
5. 实现阅读体验增强，包括可调排版、长章节分页与文字朗读（TTS）；
6. 实现管理员角色，负责用户账号与权限管理、书籍审核。

### 1.3 研究意义

**理论意义**：本课题综合运用 Web 抓取、HTML 正文提取、规则引擎、个性化排序、认证授权与前后端分离等软件工程与算法知识，是对数据库、网络、数据结构、软件设计等课程知识的综合实践，有助于理解"抓取—解析—存储—展示"的完整数据处理链路。

**实践意义**：通过"正文密度打分算法"实现后端正文清洗，从根本上保证纯净阅读体验；通过"可配置书源规则引擎"实现新增站点尽量依靠配置完成、减少代码硬编码；通过统一的"内容源管理 + 抓取解析 + 正文清洗 + 收藏阅读"处理管道同时服务新闻与书籍两类场景，体现良好的系统抽象与复用能力。系统以网站形式交付，部署方便、跨平台、易演示，具有较好的实用价值。

## 二、国内外研究现状

### 2.1 国外研究现状

在 RSS 聚合阅读领域，Feedly、Inoreader 等产品提供订阅、分类与跨平台同步，是资讯聚合的代表；在正文提取领域，Readability、Boilerpipe、Mercury 等基于启发式规则的正文抽取算法被广泛采用，其核心思想是"文本密度 + 链接密度"打分，选取得分最高的文本块作为正文。在语音合成领域，W3C 的 Web Speech API 为浏览器提供了内置的语音合成能力，Azure、Google 等云厂商也提供高质量的神经语音合成服务，为"听新闻、听书"提供了技术基础。

### 2.2 国内研究现状

在国内，开源阅读（legado）是一款广受欢迎的开源阅读应用，其"书源规则"体系允许用户通过配置 JSON 规则（含 CSS/XPath 选择器、请求头等）接入任意书籍网站，真正实现"新增站点不改代码"，是"规则驱动"设计思想的典型代表；各类资讯聚合应用（如今日头条）则依赖平台算法推荐，用户自主配置能力有限。在书籍源生态方面，笔趣阁系站点镜像众多但普遍存在反爬（字体替换、Cloudflare、限流）、域名频繁变更等问题，为爬虫设计带来挑战。

### 2.3 现状分析与本课题定位

综合来看，现有方案在"统一入口""纯净正文"与"可配置内容源"三个目标上各有侧重，但缺少整合：RSS 阅读器主要聚焦新闻订阅，无法处理书籍阅读场景；legado 面向书籍，功能依赖 Android 运行环境，难以直接移植到 Web 端；资讯聚合应用由平台算法主导，用户难以自主配置。本课题在 Web 端统一新闻源与书源两类内容源，引入管理员审核机制保证内部书库内容质量，并提供可调排版与朗读等阅读增强，是对现有方案的一次整合与完善。

## 三、课题研究的主要内容

### 3.1 用户与权限体系

设计用户/管理员双角色：普通用户注册登录后配置内容源、上传书籍、阅读；管理员负责用户账号管理（启用/禁用、角色分配、重置密码）与书籍审核（通过入库/驳回）。认证采用 JWT 无状态认证与 BCrypt 密码加密，所有个人数据按用户隔离。

### 3.2 新闻板块

1. 新闻源管理：RSS/网页源的新增、编辑、删除、启停，权重与抓取频率配置，支持一键导入推荐源；
2. 定时抓取与正文清洗：定时批量抓取 RSS/列表页，解析文章链接，逐条抓详情页并清洗正文，幂等入库；
3. 个性化资讯流：按"源权重 + 新鲜度 + 行为分"打分排序展示；
4. 文章阅读：正文展示、来源标注、收藏、阅读进度。

### 3.3 书籍板块

1. 书籍上传与审核：用户上传 TXT（或粘贴全文），系统自动识别编码并拆分章节，管理员审核通过后进入公共内部书库；
2. 内部书库搜索：按书名/作者搜索已审核书籍；
3. 书源规则引擎：规则 JSON 描述"搜索/详情/目录/正文"四环节，支持 legado 书源导入与章节分页拼接；
4. 书源搜索：内部书库搜索不到或结果不满意时，可按自定义书源聚合搜索；
5. 书籍阅读：详情、目录、章节正文、书架与阅读进度。

### 3.4 阅读增强

1. 阅读设置：字号、行距、段落间距、字间距、字体、背景主题、页宽可调；
2. 长章节分页：正文超长时自动分页；
3. 文字朗读：基于 Web Speech API 的朗读功能，支持语速/音量/音色、段落高亮。

### 3.5 关键问题与创新点

1. **多用户内容源去重**：针对"多用户订阅同一源导致入库互相去重"的问题，设计 `(source_id, url_hash)` 联合唯一键；
2. **TXT 章节自动拆分**：兼容"第X章/幕/回"、序章/尾声等多种标题，支持二字标题带空格、目录条目过滤与汉字边界判断；
3. **书源章节分页拼接**：通过"下一页"链接选择器与同一章节 `_N.html` 判断自动拼接多页正文；
4. **可配置朗读引擎抽象**：朗读层只依赖统一接口，为后续接入用户自带 Key 的云端 TTS 预留。

## 四、拟采用的研究方法（或工作方案）

### 4.1 技术路线

采用前后端分离的 B/S 架构：后端使用 Spring Boot 3.5 + MyBatis + MySQL 8 + Redis，前端使用 Vue 3 + Element Plus + Pinia + Vue Router + Axios。整体为单体应用，按"控制器—服务—数据访问"分层，新闻与书籍两个板块逻辑独立，底层复用"HTTP 抓取 + HTML 解析 + 正文清洗"通用组件。

### 4.2 关键技术

1. **正文清洗**：使用 Jsoup 解析 HTML，先移除脚本、样式、导航等干扰节点，再对文本块按"文本密度 + 链接密度"打分，选取得分最高的块作为正文，最后以白名单标签净化；
2. **书源规则引擎**：规则 JSON 描述搜索、详情、目录、正文四环节的 URL 模板与选择器，支持 CSS/XPath 选择器与 `{{key}}`、`{{bookId}}`、`{{chapterUrl}}` 占位符；
3. **章节拆分**：正则识别章节标题，按标题切分正文，并对目录、空章节、带空格标题等边界情况做处理；
4. **认证授权**：JWT 无状态认证，拦截器统一鉴权并加载用户角色，管理员接口做角色校验；
5. **个性化排序**：`score = α·源权重 + β·新鲜度(时间衰减) + γ·行为分(点击/读完)`；
6. **朗读**：Web Speech API 按句/段分块朗读，配合段落高亮与底部播放条。

### 4.3 可能遇到的困难与对策

| 困难 | 对策 |
| --- | --- |
| 不同站点正文结构差异大，正文识别不准 | 正文密度算法（通用）+ 每源自定义选择器兜底 |
| 书源易失效、反爬 | 规则 JSON 化，失效只改配置；抓取设超时与重试，失败源跳过不报错 |
| 多源并发搜索慢 | 并行抓取 + 单源超时 + 结果去重 |
| TXT 编码与章节格式多样 | 自动识别 UTF-8/GBK/UTF-16，兼容多种章节标题写法 |
| 范围失控 | 严格按范围界定，不做推荐算法、多租户、移动端等非核心功能 |
