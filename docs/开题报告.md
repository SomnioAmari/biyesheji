# 开题报告

## 基于 Spring Boot 的可配置内容源聚合与纯净阅读系统的设计与实现

---

### 一、选题背景与意义

#### 1.1 选题背景

随着移动互联网的普及，人们的阅读行为逐渐从纸质媒介转向电子媒介。然而，当前的在线阅读体验存在三个突出问题：

1. **阅读干扰严重**：新闻资讯网站与网络小说站点中充斥着大量广告、弹窗、诱导链接和无关推荐，严重干扰阅读，尤其在移动端更为明显。
2. **内容源分散**：新闻来自不同的 RSS 源与资讯站点，小说来自不同的书源，用户需要在多个应用与网站之间反复切换，缺乏统一入口。
3. **缺乏个性化与可定制性**：资讯流的排序通常由平台算法决定，用户无法按自己的关注程度调整；小说书源也经常失效，用户需要能够自行增补与维护。

针对上述问题，本课题提出构建一个**网站版的"纯净阅读器"**，将新闻资讯源与小说书源统一纳入"可配置内容源"的管理模型，由后端完成内容抓取、解析与正文清洗，从架构层面保证广告不进入阅读页，并提供收藏、阅读进度与个性化排序。

#### 1.2 选题意义

**理论意义**：本课题综合运用了 Web 爬虫、HTML 正文提取、规则引擎与个性化排序等技术，是对软件工程、数据库、算法等课程知识的综合实践。

**实践意义**：
- 通过"正文密度打分算法"实现后端正文清洗，保证纯净阅读体验；
- 通过"可配置书源规则引擎"实现新增站点尽量靠配置完成、减少硬编码；
- 通过统一的"内容源管理 + 抓取解析 + 正文清洗 + 收藏阅读"管道，同时服务新闻与小说两类场景，体现了良好的系统设计思想。

### 二、国内外研究现状

**国外现状**：RSS 聚合阅读领域有 Feedly、Inoreader 等成熟产品，提供订阅、分类与跨平台同步；正文提取领域有 Readability、Boilerpipe、Mercury 等基于启发式规则的正文抽取算法，其核心思想是"文本密度 + 链接密度"打分。

**国内现状**：开源阅读（legado）是一款广受欢迎的开源小说阅读应用，其"书源规则"体系允许用户通过配置 JSON 规则（含 CSS/XPath 选择器、JS 脚本等）接入任意小说网站，实现了"新增站点不改代码"；各类资讯聚合应用（如今日头条等）则依赖平台算法推荐。

**本课题定位**：借鉴 legado 的"书源规则"思路与 Readability 的"正文密度"思路，构建一个**简化但完整可用**的 Web 阅读系统——书源规则采用 CSS/XPath + GET/POST + 反爬请求头，正文清洗采用正文密度打分算法，资讯流采用"源权重 + 新鲜度 + 行为"的简单个性化排序。相比 legado（依赖 Android WebView、JS 引擎、验证码识别等），本系统聚焦于可工程实现的核心链路，工作量可控，适合本科毕设。

### 三、主要研究内容

1. **用户与认证**：注册、登录、JWT 无状态认证、个人数据隔离。
2. **新闻板块**：新闻源（RSS/网页源）管理、定时批量抓取、正文清洗、Redis 缓存、主页个性化排序、文章收藏与阅读进度。
3. **小说板块**：书源规则管理、书名搜索（聚合多书源、无推荐）、书籍详情、目录、章节阅读、书架。
4. **核心算法**：
   - 正文密度打分算法（文本长度 + 标点密度加分，链接密度扣分，段落容器加分）；
   - 书源规则引擎（搜索/详情/目录/正文四环节 + CSS/XPath 选择器 + POST 请求 + 提取方式）；
   - 个性化排序（`score = α·源权重 + β·新鲜度 + γ·行为分`）。
5. **配套设计**：数据库设计（11 张表）、REST API 设计、前端页面。

### 四、技术路线与方案

| 层次 | 技术选型 |
| --- | --- |
| 后端 | Spring Boot 3.5、MyBatis、MySQL 8、Redis、JWT（jjwt）、Jsoup、Lombok |
| 前端 | Vue 3、Vite、Element Plus、Pinia、Vue Router、Axios |
| 部署 | Nginx（静态托管 + 反向代理） |

**总体思路**：前后端分离。新闻板块"定时拉取 + 缓存 + 个性化"；小说板块"书源规则 + 搜索 + 书架"。正文清洗由后端完成，前端只展示干净正文。

### 五、预期成果

1. 一套可运行、可演示的完整系统（后端 + 前端 + 数据库脚本）；
2. 完整的毕设文档（需求规格说明书、概要设计说明书、详细设计说明书、测试说明）；
3. 一份可导入的"真实内容源清单"（新闻源与书源）。
